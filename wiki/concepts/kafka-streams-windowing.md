# Kafka Streams Windowing

**Источник:** [Kafka Streams in Action, Second Edition](../sources/kafka-streams-in-action.md)

## Суть

Windowing позволяет агрегировать бесконечный поток в ограниченные интервалы времени. В Kafka Streams важно правильно выбрать тип окна, `grace` для late events и политику emission (включая `suppress()` для финальных результатов).

## Типы окон

| Тип окна | Поведение | Типичный кейс |
|----------|-----------|---------------|
| **Tumbling** | Неперекрывающиеся фиксированные интервалы. | Метрики по минутам/часам. |
| **Hopping** | Фиксированные перекрывающиеся интервалы. | Скользящие KPI. |
| **Sliding** | Окна формируются по разнице timestamps событий. | Реактивные корреляции near-real-time. |
| **Session** | Интервалы по активности, закрываются по gap. | Сессии пользователей. |

## Late events, grace, suppress

- `grace` определяет, сколько ждать поздние события после nominal end окна.
- Малый `grace` уменьшает latency, но увеличивает риск потерь.
- Большой `grace` улучшает полноту, но задерживает final-результаты.
- `suppress()` позволяет не эмитить промежуточные апдейты, а отдавать только финальный результат окна.

## Практические trade-offs

- Рано закрыли окно -> недосчёт.
- Поздно закрыли окно -> высокая задержка и больший state.
- Нужен баланс по бизнес-SLO: что важнее, latency или полнота.

## Типичные вопросы на интервью

**Q: Чем tumbling отличается от hopping на практике?**  
A: Tumbling даёт одно значение на интервал без перекрытия. Hopping создаёт несколько окон для одного события, что полезно для сглаживания, но дороже по вычислениям.

**Q: Что делает grace period?**  
A: Определяет допустимое опоздание событий для окна после его конца. Поздние события после grace обычно игнорируются.

**Q: Зачем нужен suppress()?**  
A: Чтобы downstream не получал множество промежуточных апдейтов. Это полезно, когда нужен только финальный, стабильный результат окна.

**Q: Почему окна могут взрывать state?**  
A: Много ключей * много активных окон * длинный grace/retention. Это увеличивает локальный store и changelog traffic.
